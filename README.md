# Stethos marketing site

Static site in the same architecture as the Wellby Inroads site (`WellbyHealth/inroads/site`): plain HTML in `public/`, the shared Inroad/Aria CSS (`styles.css`, `v2.css`, `site.css`, `home.css`, `pricing.css`), Figtree, and clay art from FLORA.

## Structure
- Hosted on Vercel, project `stethos` (team ariapractice). Every push to `main` deploys to production. Vercel runs `python3 tools/build.py` and serves `public/`; `vercel.json` sets clean URLs, cache headers and the `/blog` rewrite.
- The production URL comes from Vercel's `VERCEL_PROJECT_PRODUCTION_URL` at build time, so canonical links, the sitemap and share tags switch to a custom domain automatically once one is added.
- `tools/` holds the page templates. Edit copy there, then run `python3 tools/build.py` to regenerate every page, `sitemap.xml`, `robots.txt` and `llms.txt`.
  - `parts.py`: brand name, domain, app URL, contact email, shared header, footer and CTA band
  - `page_home.py`: home page and FAQ
  - `page_other.py`: use cases, pricing and credit costs, compare pages, docs, privacy, 404
  - `page_blog.py`: blog index and the three guides
  - `page_uc.py`: one landing page per use case
  - `page_seo.py`: keyword landing pages
  - `posts_scheduled.py`: guides scheduled for future dates
  - `preview.py`: makes `preview/`, a copy with relative links for hosts without clean URLs
- `public/stethos.css`: the few additions on top of the shared styles (hero colors, API playground, provenance card, docs).
- `public/play.js`: the "Try a call" sample requests and responses.

## Blog schedule
- Posts live in `tools/page_blog.py` (published) and `tools/posts_scheduled.py` (scheduled). Each has a `date`.
- The build publishes only posts dated today (US Pacific) or earlier. Unpublished posts appear nowhere: not in the blog index, home strip, RSS (`/blog/rss.xml`), sitemap or `llms.txt`.
- A daily scheduled task ("Stethos blog daily release") redeploys production so posts go live on their date.
- Preview a later date locally: `STETHOS_TODAY=2026-12-31 python3 tools/build.py`.

## SEO
- Every page has a unique title (under 60 characters) and meta description (under 160), a canonical URL, Open Graph and Twitter tags, and its own 1200x630 JPG share image in `public/og/`.
- Structured data: Organization, WebSite, SoftwareApplication with offers and FAQPage on the home page; FAQPage and offers on pricing; TechArticle on docs; BlogPosting on posts; FAQPage on each use-case page; BreadcrumbList on every inner page.
- Keyword landing pages: `/npi-lookup-api`, `/physician-data-api`, `/license-verification-api`, `/health-system-data-api` (`tools/page_seo.py`).
- Each use case has its own indexable page at `/use-cases/<slug>`, linked from the hub, the nav dropdown, the footer, the home page and the blog.
- `sitemap.xml`, `robots.txt` and `llms.txt` are regenerated by the build. After launch, submit the sitemap in Google Search Console and Bing Webmaster Tools.
- Lighthouse (local build): SEO 100 and Accessibility 100 on the pages checked, home Performance 97. Vercel adds the compression and caching that a local test doesn't.
